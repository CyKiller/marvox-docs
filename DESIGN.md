# Marvox Docs Design Contract

Marvox Docs must visually align with the main Marvox platform.

## Design Personality

Marvox is a storyworld production studio, not a generic AI SaaS dashboard.

The docs should feel:
- cinematic
- technical
- editorial
- restrained
- premium
- calm
- platform-native

The docs should not feel:
- colorful
- playful
- neon
- crypto-like
- generic AI SaaS
- overly gamified
- badge-heavy
- gradient-heavy

## Visual System

Use the same core language as MarvoxV1:

- Dark obsidian / carbon background
- Cyan as the primary accent
- Manrope for UI/body text
- Cormorant Garamond for editorial display headings
- Neutral slate text hierarchy
- Subtle borders
- Low-opacity panels
- Minimal glow
- No rainbow gradients
- No purple/orange/green/yellow feature-card system unless color is semantically required

## Color Rules

Primary accent:
- Cyan / sky blue only

Allowed neutrals:
- Obsidian
- Carbon
- Slate
- Muted gray
- White text

Allowed semantic colors:
- Red only for destructive/error
- Amber only for warning
- Green only for success
- These should appear in small labels or status indicators, not whole sections.

Avoid:
- Purple AI gradients
- Orange announcement banners
- Multi-color workflow cards
- Multiple icon background colors
- Heavy glow effects
- Neon badges

## Layout Rules

- Prefer editorial sections over card walls.
- Avoid repeated 3-column feature grids.
- Use clear docs hierarchy: Start, Understand, Build, Ship.
- Use large whitespace and readable text widths.
- Keep diagrams calm and useful.
- Cards should explain, not decorate.

## Copy Rules

Use plain product language.

Avoid:
- "Elevate"
- "Unleash"
- "Next-gen"
- "Game-changing"
- "World-class"
- "99/100"
- "Production ready" unless release gates prove it

Use:
- "Private beta"
- "Production hardening"
- "Canon-grounded"
- "Storyworld runtime"
- "CharacterOS"
- "Voice pipeline"
- "Release gates"
